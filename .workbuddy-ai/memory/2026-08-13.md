## Bug Fix: Edit Exam 404 — True Root Cause

- **Issue**: Clicking the edit (pencil) icon in `src/components/exams/ExamManagementList.tsx` produced a 404 at `localhost:3000/exams/142/edit`.
- **First (wrong) hypothesis**: URL segments reversed; component built `${basePath}/edit/${id}` while file was at `${basePath}/${id}/edit`. Updated the link — still 404.
- **True root cause**: Discovered redirects in `next.config.ts`:
  ```ts
  { source: '/exams/edit/:id', destination: '/exams/:id/edit', permanent: true }
  { source: '/doctor/exams/edit/:id', destination: '/doctor/exams/:id/edit', permanent: true }
  ```
  These redirects proved the **intended** route is `/exams/:id/edit`, but the page files were physically placed at the wrong path (`app/(admin)/exams/edit/[id]/page.tsx`). Both URL forms were therefore 404ing:
  - `/exams/142/edit` → no `[id]/edit/page.tsx` existed.
  - `/exams/edit/142` → redirect rewrote it back to `/exams/142/edit` → 404.
- **Fix**: Moved the page files to match the intended route (and the existing redirect config):
  - `app/(admin)/exams/edit/[id]/page.tsx` → `app/(admin)/exams/[id]/edit/page.tsx`
  - `app/(doctor)/doctor/exams/edit/[id]/page.tsx` → `app/(doctor)/doctor/exams/[id]/edit/page.tsx`
  - Removed now-empty `exams/edit/` and `doctor/exams/edit/` directories.
  - Reverted the unrelated link change in `ExamManagementList.tsx` so it still emits `${basePath}/${quiz.id}/edit`.
- **Final route layout (verified)**:
  - `app/(admin)/exams/[id]/edit/page.tsx` → `/exams/:id/edit`
  - `app/(admin)/exams/[id]/results/page.tsx` → `/exams/:id/results`
  - `app/(doctor)/doctor/exams/[id]/edit/page.tsx` → `/doctor/exams/:id/edit`
  - `app/(doctor)/doctor/exams/[id]/results/page.tsx` → `/doctor/exams/:id/results`
- **Takeaway**: When a 404 persists after a link fix, check `next.config.ts` redirects. A pre-existing redirect is strong evidence of intended URL shape — the file location is what's wrong, not the link.

## Follow-up: Tailwind watcher cache after move

- After moving the page files, the rebuild failed with `ENOENT: no such file or directory, stat 'app/(admin)/exams/edit/[id]/page.tsx'` raised inside `tailwindcss/lib/lib/content.js` → `resolveChangedFiles`.
- Cause: Turbopack/Tailwind's change-watcher kept polling the now-missing old path during CSS evaluation.
- Fix: `rm -rf .next/cache .next/build .next/server tsconfig.tsbuildinfo` then restart `npm run dev`. The watcher re-indexes against current filesystem state.
- Going forward, prefer renaming a route segment instead of moving files wholesale when possible — and remember to clear `.next/cache` whenever a route file disappears/moves.
